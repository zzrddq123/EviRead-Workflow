# EviRead CodeBase1 — BioLM-only

This is the corrected first codebase. Its executable profile is `EVIREAD_PROFILE=model_only` and its only biological evidence channels are ESM2, ESMC, and ProTrek. It is the prediction/RSI side of the experiment; the canonical FunctionBench-Bio-GAF1389 benchmark and evaluator are external and own the Gold, ontology scoring, and final metric. EviRead exports the standard `target_id\tgo_id\tscore` prediction surface, which is then passed to `/path/to/FunctionBench-Bio-GAF1389/evaluator/evaluate_candidate.py` by an evaluator-side wrapper. The inherited LatestRSI controller supplies the experiment/RSI machinery; the model-only profile bypasses the conventional evidence runner and fails closed if a tool provider is configured or appears in the BioLM artifact.

The first Read implementation is in `src/eviread_read.ts`. It compiles model observations into structured evidence plus deterministic text. `python/biolm.py` and `python/biolm_embed.py` are the real GPU backend: they launch the pinned ESM2, ESMC, and ProTrek environments, compute residue-weighted 1022-residue-chunk embeddings, L2-normalize them, retrieve cosine neighbors from a hash-bound index, and emit `biolm-evidence.v1`. The machine-local GPU deployment helper is kept separately at `/path/to/eviread-host/`; it is not part of the portable paper/code release.

The unified CodeBase1 prediction path is now: BioLM evidence construction → deterministic evidence/ontology preprocessing → mandatory semantic GO Agent judgment → final GO selection and export. Deterministic code is a component of the single pipeline, not an alternative functional predictor. `EVIREAD_REQUIRE_SEMANTIC_GO_AGENT=1` makes this contract fail closed if a non-semantic genome is selected. RSI may optimize how the semantic Agent uses BioLM candidates, donor contexts, evidence budgets, thresholds, retention, and provenance gates, but must not silently switch to a different predictor architecture.

The only production RSI entry point is the complete Git/program-level LatestRSI controller: `./pi-agent rsi autonomous-rsi-production-start --profile /absolute/production-start-profile.json`. The historical external policy sweep scripts and the former `python/codebase1_rsi.py` policy runner are not part of this framework; they were removed from the active tree and archived outside the repository. The production controller owns exact candidate commits/worktrees, Diagnose/Research/Plan/Develop/Verify/Evaluate, persistent history/tree search, aggregate-only evaluation, rollback, freeze, and promotion.

The development/validation evaluator must run outside the candidate process, return aggregate-only metrics, and keep private Gold and accession mappings unavailable to EviRead. CodeBase2 is intentionally not this profile. It will be a separate augmented resource plane adding BLAST/Foldseek/OMA/InterPro and other tools, followed by its own RSI campaign.

All model calls (semantic GO judgment, synthesis/review, method development, patch harness and LatestRSI workers) now execute through `src/codex_runtime.ts` using the locally authenticated `codex exec --model gpt-5.6-sol` with high reasoning. The Pi package remains only for compatible tool/resource types; the `pi-agent` launcher name is retained. No Pi CLI/sidecar is used for inference. Host tool dispatch and validation remain in charge. Run `npm run smoke:codex` to verify a real structured Host-tool submission (90-second smoke deadline). `smoke:pi` remains a compatibility alias. Codex must be on PATH or at `$HOME/.local/bin/codex`; workers inherit explicitly allowlisted Codex routing settings.

Transport follows [OpenAI non-interactive Codex documentation](https://learn.chatgpt.com/docs/non-interactive-mode) (`--json`, `--output-schema`, `--output-last-message`). Model/account availability must be established by the local smoke test, not inferred from CLI installation. A transport migration does not make an existing frozen campaign or historical release manifest match the new source; prepare a new verified source/campaign binding before a formal iteration.

For training-first RSI, use `scripts/prepare_training_gated_profile.py` to snapshot a new Host evaluator, baseline policy, data-split manifest and production profile outside the candidate repository. The policy enables evaluator-only validation feedback during RSI: every candidate is scored on training; validation is skipped below `baselineRatio × strongest non-diagnostic train baseline` (default ratio 0.90). At/above the gate, validation contributes aggregate feedback and the loop continues. The primary objective remains `training_macro_fmax` across both phases; a skipped validation score is null, never a fabricated zero or a relabeled training score. Validation feedback can guide the next agent plan, but does not automatically stop or select the final candidate by validation score. The existing iteration budget and explicit diagnosis stop remain; generated profiles set plateau patience to the iteration budget. Test stays frozen until final evaluation. `after_freeze_only` manifests remain supported and are never silently opened.

The generated evaluator and policy are copied into a new Host directory and bound by hashes. Old campaigns and their frozen manifests are unchanged. This is a development-time validation policy, so these validation results must not be presented as an untouched final test. Use the new source/campaign binding for a formal run.

High similarity never excludes a donor in Codebase1. This includes 99–100% sequence identity, cosine near 1, and an identical sequence hash. BioLM retrieval applies its ordinary top-k/minimum-score ranking, then integrates retained donor evidence. Explicit operator exclusions are separate; they are never inferred from similarity. The full cached retrieval path was checked against all 83,340 retained observations, including 1,653 identical-sequence observations.

Current source integrity is checked with `python3 scripts/verify_iclr_composition.py` and `python3 scripts/verify_rsi_release.py`, using the new `config/codebase1-codex-rsi-release.json`. Historical R09 provenance and the old operational inventory remain preserved; `verify_iclr_composition.py --historical-only` deliberately tests the different, historical byte-identity claim. The historical test genome is explicitly rebound in a temporary test fixture; stale contract hashes are still rejected.
